# ROW LEVEL SECURITY

This is extremely important.

Enable RLS on all user-related tables.

Examples:

### Profiles

Users can update their own profile.

### Creator profiles

Creators can update their own information.

Public creator information can be read according to the application's visibility rules.

### Businesses

Businesses can update only their own business profile.

### Campaigns

Businesses can create/update their own campaigns.

Creators can view eligible public campaigns.

### Messages

Only conversation participants can read/write messages.

### Payments

Users must never be able to modify payment records directly.

Use server-side verification/webhooks for payment updates.
